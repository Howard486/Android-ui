# 桌面改版：通用 / 工作 / 簡易

定案於 2026-08-22。取代 V0.1 那個「由使用量算出來」的桌面，改成使用者自己
擺放的可編輯桌面。

## 為什麼這是一次重寫，而不是調整

V0.1 的桌面沒有頁面、沒有格子、沒有持久化的位置——Dock 由 UsageStats 算出
來，App 抽屜列出全部。使用者要的是相反的模型：固定格線、自己擺、資料夾、
小工具、翻頁。

受影響的只有桌面那一層。Context Engine、通知分級、Power Dock、主題系統、
手勢仲裁與 Samsung Wallet 保留區完全不動，直接接上新桌面。

## 三個模式

### 通用

- **沒有 App 抽屜。** App 只存在於桌面頁面上。
- **保留上滑搜尋。** 這不是抽屜、不列全部，只是搜尋框。沒有它，在 5 頁裡
  找一個 App 會比開抽屜打字慢得多——拿掉抽屜不該讓使用者付出這個代價。
- 格線：折疊 5×7，展開另一套（見下）。
- 一鍵整理分類，可預覽、可還原。
- 小工具可放在任何頁面，另外保留一個專屬 widget 頁籤。
- 最左頁是 feed 頁。

### 工作

- 版面偏重 Outlook / Teams / 行事曆。
- 「整理工項」以**通知衍生**實作：既有的 NotificationListener 把 Outlook /
  Teams 通知歸成工作項目清單，點擊 deep link 回原 App。
- 已知限制，要對使用者說清楚：**只看得到有發通知的東西**。通知關閉或已被
  清除的項目不會出現。
- Microsoft Graph 登入（真正的收件匣 / To Do）不在此次範圍。

### 簡易

- 放大的時鐘 + 4 個使用者自選的 App。
- 沿用同一套 layout 資料表（space=simple、2×2 格線），不另開一套模型。
- 主題固定 True Black，密度固定 Simplified。
- **Context Engine 永遠不會把使用者切到這裡**（見 `SpaceId.isUserSelectableOnly`）。

## 格線與摺疊

| 姿態 | 格線 | 依據 |
|---|---|---|
| 折疊（外螢幕，約 387dp 寬） | 5×7 | 每格約 77dp，與一般 Launcher 的 5 欄相當 |
| 展開（內螢幕，約 940dp 寬） | 8×6 | 同樣 5 欄會變成每格 188dp，大得荒謬 |

dp 數字為粗算，**需實機量測確認**（§22）。

**展開後是獨立版面**，不是把折疊版重排。首次展開時從折疊版自動生成一份，
之後兩份各自獨立。這符合規格 §4.2「展開不是把 Folded UI 放大」，代價是要
維護兩份排列。

## 一鍵整理分類

分類來源，依序：

1. `ApplicationInfo.category`（官方，但**很多 App 根本沒填**，實測覆蓋率
   約一半）
2. 內建的台灣常用 App 對照表（LINE、蝦皮、街口、中華電信這類）
3. Gemini Nano — 這正好是它最適合的用途：使用者按下按鈕才跑（前景 ✓）、
   一次一批（✓）、結果按套件名快取（✓）、規則解不掉（✓）。裝置不支援時
   直接跳過，不阻斷功能。
4. 以上皆無 → 「其他」

**必須可還原。** 一鍵重排整個桌面卻不能反悔，是不友善的設計。流程是
預覽 → 套用 → 一鍵還原（單層快照）。

## 最左頁：feed

第三方 Launcher 接 Google Discover 的實情：做得到，但通常需要一個橋接
App，Google 又把新版 feed 樣式限定給 Pixel Launcher 的套件名，且長期有
「不會動」的回報，行為隨裝置與 Google App 版本而異。在 Galaxy Z Fold 上
是否可行**無法保證，只能實機驗**。

所以最左頁是**我們自己的頁面**，feed 來源是可抽換的 provider：

- Provider A：Google overlay（含橋接）——優先嘗試
- Provider B：Google News 公開 RSS——接不上時的備援

不是個人化的 Discover，但最左滑一定有內容，不依賴 Google 放行。

## 階段

| 階段 | 內容 |
|---|---|
| 0 | 實機探路：Google overlay 在 Fold 上綁不綁得上（併入階段 1） |
| 1 | 桌面資料模型：Room（page / item / folder / widget）、格線引擎、首次啟動排入所有 App、安裝移除自動增刪、拿掉抽屜改為搜尋 |
| 2 | 簡易模式（小，但能驗證整個模型） |
| 3 | 編輯：長按拖放、跨頁移動、拖曳成資料夾、一鍵整理分類（含預覽與還原） |
| 4 | 小工具：AppWidgetHost、選擇器、綁定授權、調整大小、持久化、折疊時重新量測 |
| 5 | 最左 feed 頁 + 可抽換 provider |
| 6 | 工作模式：通知衍生工項、分組、deep link |

## 對既有程式的影響

- **App 抽屜 → 純搜尋。** `AppDrawer` 縮成搜尋 + 建議，不再列出全部。
- **Dynamic Dock 的智慧格**與「使用者自己擺」在通用模式相衝突。通用模式
  只留使用者釘選的；智慧格保留在工作模式，那裡情境判斷才有意義。
- **Room 到這裡才有存在理由。** V0.1 的 README 說「等到有關聯式資料再引入
  Room」——頁面、格子、資料夾、widget 綁定就是那個時刻。

## 未決 / 待驗

- 5×7 與 8×6 的實際 dp 需在 Fold 實機量測。
- Google overlay 在 One UI 上的可行性（階段 0）。
- `ms-outlook://` deep link 只有社群文件、無微軟正式文件，每條都要實機驗。
- 沒有抽屜時「隱藏 App」的語意：不在任何頁面上 = 只能靠搜尋找到。待定。
